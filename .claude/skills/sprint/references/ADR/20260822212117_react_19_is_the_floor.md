# React 19 is the floor

- **Status**: Accepted
- **Date**: 2026-08-22

## Context

`package.json` declared `"react": "^18.3.0 || ^19.0.0"`. Button cannot honour it.

R5.4 requires every component to accept `ref` and spread the rest onto its root, and Button
implements that the React 19 way: `ButtonProps extends ComponentPropsWithRef<"button">` and the
component destructures `ref` straight out of `props`. Under React 18 a function component never
receives `ref` in `props` — React strips it and warns — so on the declared floor Button silently
loses its ref, `element.current` stays `null`, and the press tool falls through to the
`agentControls="never"` path that the render-mode ADR describes as the opt-out route. Nothing in CI
would notice: the dev dependency is React 19, so the 18 half of the range was never built or tested.

The declared range was aspiration, not support. It has been wrong since the first component, and
every component after Button repeats the same pattern.

## Decision

**`react` and `react-dom` peer ranges become `^19.0.0`.**

The alternative — wrapping every component in `forwardRef` to keep 18 working — was rejected. It
costs a wrapper per component forever, in a library whose whole authoring cost argument (PRD success
criteria) is that a component should be cheap to add. Ref-as-prop is also not the only 19 dependency
in the design's path: `useAgentTool`'s registration lifecycle and `commitSync`'s `flushSync` usage
are both easier to reason about under 19's semantics, and the catalogue is about to grow.

Sprint is pre-1.0 with one component and no consumers. Widening later is a minor release; shipping
a range that does not work is a bug report.

## Consequences

**Easier:**

- Components stay plain functions. No `forwardRef` wrapper, no generic-erasure workarounds.
- The tested configuration and the declared configuration are the same one.

**Harder:**

- An application still on React 18 cannot adopt Sprint. Acceptable now, and the honest position
  either way — it could not have adopted it before this change either, it would just have found out
  at runtime.

**Follow-up:**

- If the 18 case ever earns its keep, it needs a real CI matrix entry, not a widened range.
